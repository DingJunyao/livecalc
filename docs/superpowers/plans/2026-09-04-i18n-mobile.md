# Mobile i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver Flutter localization, user locale synchronization, locale-aware display formatting, complete mobile UI translations, and Arabic RTL support on `feat/i18n-mobile`.

**Architecture:** Flutter owns UI translation through official `gen-l10n` ARB catalogs and resolves one effective UI locale from the logged-in user, cached mobile preference, or system locale. A Riverpod-backed locale controller feeds `MaterialApp`, a Dio interceptor, and an `intl` formatter facade. Translation work is batched by feature so every batch can be tested independently while backend and Web remain unchanged from the merged `feat/i18n` result.

**Tech Stack:** Flutter, `flutter_localizations`, `flutter gen-l10n`, `intl`, Riverpod, Dio, SharedPreferences, Flutter widget testing.

**Spec:** `docs/superpowers/specs/2026-08-30-i18n-design.md`

## Global Constraints

- This plan executes only on `feat/i18n-mobile`; do not add mobile changes to `feat/i18n`.
- UI locales are exactly `zh-CN`, `en-US`, and `ar`; unsupported values fall back to `zh-CN`.
- Format locales are exactly `null`, `zh-CN`, `zh-TW`, `en-US`, `en-GB`, `ja-JP`, `de-DE`, `id-ID`, and `ar-EG`.
- `locale` controls text and direction; `format_locale` controls display formatting only.
- Logged-in users use server preferences; mobile local storage may cache the last authenticated preference for startup restoration; after logout the app returns to system locale.
- Dio sends the effective UI locale as `Accept-Language` and continues sending the existing `X-Timezone`.
- Preserve existing `X-Currency` and `X-Region` behavior.
- API dates remain ISO strings, numbers remain decimal values, and currency remains ISO code plus numeric amount.
- Do not rewrite form input parsing for locale decimal separators or date orders.
- Logs, stack traces, comments, and internal exceptions remain untranslated.
- Charts, maps, and geographic coordinates remain LTR; do not flip longitude, latitude, time values, or chart axes.
- Do not translate user/business data such as merchant names, product names, user notes, or proposal payload values.
- Every task uses TDD: write the named test first, watch it fail for the missing behavior, then implement.
- Mobile verification commands are `flutter gen-l10n`, `flutter analyze`, and focused/full `flutter test` as listed.
- If Flutter is unavailable in the execution environment, stop before production-code changes and record the SDK blocker; static edits without red/green test evidence are not acceptable.

## File Structure

- `mobile/l10n.yaml`: gen-l10n configuration.
- `mobile/lib/l10n/app_zh.arb`: template Chinese catalog.
- `mobile/lib/l10n/app_en.arb`: English catalog.
- `mobile/lib/l10n/app_ar.arb`: Arabic catalog.
- `mobile/lib/core/i18n/app_locale.dart`: locale whitelists, normalization, system matching, and Flutter locale mapping.
- `mobile/lib/core/i18n/locale_settings.dart`: locale state, persistence, user synchronization, and request-header store.
- `mobile/lib/core/i18n/app_formatters.dart`: date, time, number, percent, and money display formatting.
- `mobile/lib/core/api/locale_interceptor.dart`: `Accept-Language` request interceptor.
- `mobile/test/core/i18n/`: locale, persistence, and formatter tests.
- Existing feature files are modified only to consume generated localizations and formatters; no backend or Web source is changed by this plan.

import 'package:flutter_test/flutter_test.dart';
import 'package:com_a4ding_livecalc/core/i18n/app_locale.dart';

void main() {
  test('locale whitelists match the shared specification', () {
    expect(supportedUiLocales, ['zh-CN', 'en-US', 'ar']);
    expect(supportedFormatLocales, {
      'zh-CN',
      'zh-TW',
      'en-US',
      'en-GB',
      'ja-JP',
      'de-DE',
      'id-ID',
      'ar-EG',
    });
    expect(defaultUiLocale, 'zh-CN');
  });

  test('server locale wins, cache is second, then normalized system locale', () {
    expect(
      resolveUiLocale(
        userLocale: 'ar',
        cachedLocale: 'en-US',
        systemLocales: const [Locale('zh', 'CN')],
      ),
      'ar',
    );
    expect(
      resolveUiLocale(
        cachedLocale: 'en-US',
        systemLocales: const [Locale('zh', 'CN')],
      ),
      'en-US',
    );
    expect(
      resolveUiLocale(systemLocales: const [
        Locale('fr', 'FR'),
        Locale('zh', 'Hans', 'CN'),
      ]),
      'zh-CN',
    );
    expect(resolveUiLocale(systemLocales: const [Locale('en')]), 'en-US');
    expect(resolveUiLocale(systemLocales: const [Locale('ar')]), 'ar');
    expect(resolveUiLocale(systemLocales: const []), 'zh-CN');
  });

  test('format locale follows explicit choice or UI default', () {
    expect(effectiveFormatLocale(uiLocale: 'ar'), 'ar-EG');
    expect(
      effectiveFormatLocale(uiLocale: 'ar', formatLocale: 'de-DE'),
      'de-DE',
    );
    expect(
      effectiveFormatLocale(uiLocale: 'zh-CN', formatLocale: 'unsupported'),
      'zh-CN',
    );
    expect(flutterLocaleFor('zh-CN'), const Locale('zh', 'CN'));
    expect(flutterLocaleFor('en-US'), const Locale('en', 'US'));
    expect(flutterLocaleFor('ar'), const Locale('ar'));
  });
}
