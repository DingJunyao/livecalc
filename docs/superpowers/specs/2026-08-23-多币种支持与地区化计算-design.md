# 多币种支持与地区化计算设计

## 背景

当前系统价格记录虽已有 `currency` 与 `exchange_rate` 字段，但 `exchange_rate` 恒为 1.0（代码留有 TODO），原料/商品价格、菜谱成本、报告等聚合结果全部硬编码 `CNY`。商家没有地区字段，成本计算按用户全量记录聚合，不区分地区物价。本设计为系统增加多币种支持，并将价格/成本计算按商家所在地区（国家/省市）过滤。

## 目标

- 币种按国家/地区默认：一个国家/地区对应一个默认币种。
- 商家有默认地区；价格记录归属商家，继承其币种；记录时可覆盖币种。
- 记录价格时商家必填，输入框位于商品之前；选择商家后自动带出其币种符号，可点击符号弹出下拉指定其它币种。
- 用户可设置自己的默认币种（直接指定或跟随所在地区）。
- 价格记录展示以原币种为主，附带记录时汇率折算的用户币种金额。
- 聚合结果（原料/商品价格、菜谱成本、报告）以用户币种显示。
- 价格/成本计算支持按地区过滤（所选地区及其全部下级），默认使用用户的默认计算范围。
- 商家地区支持地图选点自动反查（地图功能开启且有地理编码配置时），行政区划始终可手动下拉选取。
- 汇率支持配置化 provider（默认 Frankfurter）、每日快照缓存、手动维护与离线兜底。

## 非目标

- 不做实时汇率（按日快照即可）。
- 不为无商家历史记录伪造地区。
- 不改变商品/原料共享实体模型（商品与原料仍全局共享，仅价格记录按地区参与计算）。
- 不引入 Alembic；表结构变更按项目惯例提供 SQLite/MySQL/PostgreSQL 三方言 SQL 脚本。

## 总体方案

- 新增币种字典与每日汇率快照表；`RegionUnitSetting` 增加默认币种列，作为「国家/地区 → 默认币种」映射。
- 商家增加地区与可选默认币种；用户增加默认币种与默认计算范围。
- 记录价格时由后端按当日快照计算 `exchange_rate`（原币种 → 用户当时默认币种）并随记录保存，聚合与展示均使用该快照。
- 计算层（原料加权价格、菜谱成本、报告等）统一增加 `region_id` 参数，按商家地区子树过滤价格记录，再以快照汇率折算用户币种后聚合（方案 A：查询层过滤）。
- 商家表单提供地图选点反查行政区划（受地图开关与地理编码配置控制），手动级联下拉始终可用。

## 分支与合并策略

- `feat/mobile-app` 合并 `master` 获取后端/Web 变更。

## 数据模型

### currencies（新表）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| code | CHAR(3) PK | ISO 4217 币种代码 |
| name | VARCHAR(100) | 币种名称 |
| symbol | VARCHAR(10) | 符号，如 ¥/$/€ |
| decimals | INT 默认 2 | 小数位 |
| is_active | BOOLEAN 默认 true | 是否可用 |

Seed 常见币种：CNY、USD、EUR、GBP、JPY、HKD、KRW、SGD、AUD、CAD、TWD、THB、MYR、VND、RUB 等；后台可增补。

### RegionUnitSetting（加列）

- `default_currency` VARCHAR(3) 可空：该地区代码（国家）的默认币种。取商家/用户默认币种时：沿 `AdministrativeRegion` 祖先链找到国家节点 → `iso_country` → 查本表 `default_currency` → 兜底全局默认（CNY）。

### Merchant（加列）

- `region_id` FK → `administrative_regions.id`，可空（UI 必填，遗留数据靠脚本排查）。
- `default_currency` VARCHAR(3) 可空：空 = 跟随地区国家币种；非空 = 覆盖。

### User（加列）

- `default_currency` VARCHAR(3) 可空：空 = 跟随 `user.region_id` 所在国家币种；非空 = 手动覆盖。
- `default_calc_scope` VARCHAR(10) 可空：`country`（国家/地区）/ `province`（省级）/ `city`（地级）/ `county`（县级）。默认 `country`（全量，保持现有行为）。运行时由 `user.region_id` 沿祖先链取对应层级节点作为默认计算地区；`region_id` 未设置 → 不设过滤（全部地区）。页面地区选择器可临时覆盖。

### ProductRecord（加列 + 语义明确）

- 新增 `user_currency` VARCHAR(3)：写入时用户默认币种快照。
- 既有 `currency`：记录原币种。
- 既有 `exchange_rate`：记录时 1 单位 `currency` 折算为 `user_currency` 的倍数（`exchange_rate = 1` 表示原币种 == user_currency）。
- 地区不冗余在记录上，查询时 JOIN `merchants.region_id`。

### exchange_rate_snapshots（新表）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | INT PK | |
| rate_date | DATE | 汇率适用日期 |
| base_currency | CHAR(3) | 基准币种 |
| rates | JSON | {币种: 对基准汇率} |
| source | VARCHAR(50) | provider 名 |
| fetched_at | DATETIME | 拉取时间 |

`UNIQUE(rate_date, base_currency)`。换算 `convert(amount, from, to, date)`：`amount × rate[to] / rate[from]`（相对同一基准）；`date` 无记录时向前取最近一天；都没有且 from==to 时为 1，否则视为不可换算。

## 汇率服务

- provider 注册表（仿 translate 服务 registry 模式），默认 `frankfurter`（api.frankfurter.dev，免费、无密钥、201 币种、历史可回溯、可自托管），支持配置其它 provider（如 exchange-rate-api 带 key）。
- APScheduler 每日任务：拉取当日汇率 → upsert 快照表。后台提供「立即刷新」端点。
- 手动维护端点（管理员）：补/改某日某币种汇率。
- 离线兜底：拉取失败用最近快照；完全缺失时该记录允许手动填 `exchange_rate`。
- 记录写入时：后端根据记录币种与用户当前默认币种，取当日（或最近）快照计算 `exchange_rate` 并写入 `user_currency`。

## 商家地区：自动反查 + 手动兜底

- 新增 `GeocodingService`：按 `MapConfiguration.geocoding`（已预留字段）配置的 provider（高德/百度/腾讯）调 regeo，返回 adcode → 匹配 `AdministrativeRegion.code` → `region_id`。
- 启用条件：`map_enabled = true` 且对应 provider 已配 key；不满足或反查失败 → 不自动填，走手动。
- 商家表单：行政区划级联下拉（复用 `GET /regions` 懒加载树，国家→省→市）始终可用；地图选点时自动反查填充，用户可再手动改。

## 计算层：按地区过滤（方案 A）

- 价格/成本服务统一增加 `region_id` 参数，串入：
  - 原料加权价格（`ingredient_price_service` / `resolve_direct_weighted_for_cost`）
  - 菜谱成本 / 成本区间 / 成本趋势（`recipe_service`）
  - 报告（`report_service`）、价格趋势、sparkline、按商家成本卡
- 子树过滤：`merchants.region_id` 落在所选地区子树内，用 `path` 前缀匹配（`region.path LIKE '<选中节点path>%'`）实现，递归 CTE 兜底。
- 币种折算：每条参与记录用 `exchange_rate` 快照折算成用户币种再聚合；`currency == 用户当前默认币种` 时倍率为 1。
- 无商家/无地区记录：开启地区过滤时排除；「全部地区」模式包含。
- 地区选择器：默认 = 用户默认计算范围（`default_calc_scope` 推导），可切换。

## 前端（Web + 移动端 Flutter）

### 价格记录表单

- 商家改为必填，置于商品字段之前（Autocomplete）。
- 选择商家后，价格输入框前缀自动带出其默认币种符号；点击符号弹出下拉可选择其它币种（记录时指定）。
- 保存时后端计算 `exchange_rate` 快照；页面可显示「≈ 用户币种金额」。

### 价格记录展示

- 原币种为主，旁边小字显示记录时汇率折算的用户币种金额。

### 聚合结果展示

- 原料/商品价格、菜谱成本、报告一律用户币种。
- 计算相关页面提供地区选择器（默认用户默认计算范围）。

### 商家表单

- 地区级联下拉 + 地图选点自动反查（受地图开关/地理编码配置控制）。

### 个人中心

- 默认币种设置（直接选 / 跟随地区）。
- 默认计算范围设置（国家/省级/地级/县级）。

### 本地模式

- 前端纯本地模式同步实现等价逻辑（币种字典、汇率、地区过滤）。

- 币种维护页：增补/停用币种（code、symbol、decimals）。

## 风险与注意

- 历史无商家/无地区记录在区域计算中不可见（提供检查脚本，不伪造数据）。
- 用户改默认币种后历史 `exchange_rate` 需重算，重算依赖快照表完整性。
- 逆地理编码依赖地图服务商配额与 key，失败时手动兜底。
- Frankfurter 覆盖主流币种；小众币种靠手动维护。
- 本地模式与后端模式数据口径需保持一致。
