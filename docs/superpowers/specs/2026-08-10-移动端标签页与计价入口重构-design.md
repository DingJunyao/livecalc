# 移动端标签页与计价入口重构 — 设计

> 日期：2026-08-10
> 分支：feat/mobile-app
> 范围：仅移动端（`mobile/`），不涉及 web 前端与后端

## 背景与目标

移动端目前有 7 个一级功能页（推荐/计价/菜谱/原料/商品/商家/我的），但底部导航栏只能放 4 个（[app_router.dart](mobile/lib/core/router/app_router.dart) `ScaffoldWithNavBar`：首页/计价/菜谱/我的）。原料、商品、商家被埋在内部导航里，用户无法从导航栏直达。

目标：

1. 底栏改为 推荐 / 计价 / 菜谱 / **更多**（汉堡图标），更多弹出二级菜单：原料/商品/商家/我的
2. 「我的」新增**启动时起始页**配置（本地存储，不上云端），可选：推荐/计价/菜谱
3. 长按「计价」直达新增价格记录；顺带修复计价页加号错误指向快速填写的 bug

## 决策记录（用户澄清结论）

| 问题 | 结论 |
|---|---|
| 长按「计价」的意图 | 与计价页加号相同：打开**新增价格记录**。并发现当前加号行为错误（指向快速填写） |
| 更多菜单形式 | **底部弹出菜单**（showModalBottomSheet），Material 3 常见交互 |
| 桌面/平板（≥600px）侧边栏 | **7 项全展示**，不设「更多」（空间充裕，响应式惯例） |
| 长按计价是否切页 | 先切到计价 tab，再打开表单；返回/保存后落在计价页 |
| 新增价格记录表单形式 | 手机上表单较复杂，用**独立全屏页面**（web 端是对话框） |
| 底栏实现 | **方案 A：自绘**（Row + InkWell，外观对齐 M3 NavigationBar）；原生组件不支持 per-destination 长按，方案 B（Overlay hack）已否决 |

## 1. 导航架构

### 手机底栏（<600px，自绘）

| 项 | 图标 | 路由 | 行为 |
|---|---|---|---|
| 推荐 | home | `/home` | 单击切换（原「首页」改名「推荐」） |
| 计价 | receipt_long | `/prices` | 单击切换；**长按** → 切到计价 tab 并打开新增价格记录页 |
| 菜谱 | restaurant | `/recipes` | 单击切换 |
| 更多 | menu（汉堡） | — | 单击弹出底部菜单：原料/商品/商家/我的 |

- 自绘组件：`Row` + 每项 `InkWell`（onTap / onLongPress），选中态样式对齐 M3 NavigationBar（图标+label，选中点状指示器等外观尽量贴近）
- 更多菜单：`showModalBottomSheet`，4 个 `ListTile`，点击后关闭菜单并 `context.go()` 到对应路由

### 桌面 Rail（≥600px）

原生 `NavigationRail`，7 项全展示：推荐/计价/菜谱/原料/商品/商家/我的。无「更多」，无长按。

### 选中态规则（手机 + 桌面统一）

按**路由前缀**分组匹配：

- `/home` → 推荐；`/prices*` → 计价；`/recipes*` → 菜谱
- `/ingredients*`、`/products*`、`/merchants*`、`/profile*` → 更多（手机）/ 各自项（桌面）

改进说明：现状是 `_tabRoutes.indexOf(matchedLocation)` 精确全等，进详情页（如 `/recipes/123`）后选中态丢失。改为前缀分组后详情页也高亮所属 tab。

## 2. 计价入口重排（[price_list_screen.dart](mobile/lib/features/prices/screens/price_list_screen.dart)）

1. **FAB 加号修复**：现为 `context.push('/prices/quick-fill')`（错误）→ 改为打开**新增价格记录页**（第 3 节），对齐 web 端加号 = 添加价格记录对话框
2. **快速填写入口**：AppBar actions 新增 `Icons.bolt` IconButton → `/prices/quick-fill`，对齐 web `mdi-lightning-bolt`（[PricesView.vue:8](frontend/src/views/prices/PricesView.vue#L8)）
3. **长按「计价」tab**：`context.go('/prices')` 切 tab → 打开新增价格记录页；保存或返回后自然落在计价页

FAB 与长按共用同一新增入口。空态文案「点击右下角按钮记下第一笔价格」保持不变。

## 3. 新增价格记录全屏页

新建 `mobile/lib/features/prices/screens/price_record_form_screen.dart`，路由 `/prices/record`（Shell 内，对齐 quick-fill 现有模式）。

### 字段（对齐 web 对话框 [PricesView.vue:170-308](frontend/src/views/prices/PricesView.vue#L170-L308)）

| 字段 | 控件 | 说明 |
|---|---|---|
| 商品名称 | Autocomplete 搜索 | 复用 `ProductRepository.search()`；未匹配可输入新商品名直接创建（对齐 web「将创建新商品」，`createRecord` 传 `productName`） |
| 价格 | 数字输入 | 必填 > 0 |
| 数量 + 单位 | 数字输入 + 下拉 | 默认 1；单位用现有 `priceRecordUnits`，默认「斤」 |
| 商家 | 下拉 | 可选，`merchantListProvider` |
| 计入支出 | Switch | 对齐 web 复选框 → `recordType: purchase / price` |
| 记录时间 | 点击修改 | 默认当前时间，可改（日期 + 时间选择） |
| 备注 | 多行输入 | 可选 |

### 保存流程

校验 → `PriceRepository.createRecord` → 返回 → 计价页 `loadRecords()` 刷新列表。

### 范围边界

- 现有 5 处 `showPriceRecordFormSheet` 调用（原料/商品上下文，带预填的就地弹窗）**不动**，[price_record_form_sheet.dart](mobile/lib/shared/widgets/price_record_form_sheet.dart) 保留
- 本次只做**新增模式**；页面表单为独立 state，将来编辑模式只需加 initial 预填参数（YAGNI，不做）
- 页面通过 **repository 注入**支持测试（对齐 `MerchantListScreen.merchantRepository` 注入模式）

## 4. 启动时起始页配置

**配置入口**：「我的」页（[profile_screen.dart](mobile/lib/features/profile/screens/profile_screen.dart)）设置区（单位偏好/营养目标下方）新增 ListTile「启动时起始页」→ 对话框单选：推荐 / 计价 / 菜谱。

**存储**：`SharedPreferences`，键 `startup_page`，值 = 路由段（`home` / `prices` / `recipes`）。纯本地。对齐 `merchants_map_current_place_id` 的存取模式。

**生效机制**：

- 新增 `startupPageProvider`（仿 [serverConfigProvider](mobile/lib/features/auth/providers/server_provider.dart) 的 load 模式），[app.dart](mobile/lib/app.dart) `_bootstrap()` 启动时加载一次
- [app_router.dart:58](mobile/lib/core/router/app_router.dart#L58) 认证后 redirect 从写死的 `'/home'` 改为 `'/<配置>'`；只影响启动初始落点，日常 tab 切换不受影响
- 桌面、手机同一套逻辑
- 默认值：推荐（`home`），不配置时行为与现状一致

## 5. 测试计划（TDD）

1. **底栏**：手机 4 项；更多弹出 4 项菜单；菜单项切换路由；选中态（含详情页前缀匹配、二级页「更多」高亮）；长按计价 → 切 tab + 打开表单页；桌面 7 项无更多
2. **计价页**：FAB → 打开新增页（非 quick-fill）；AppBar bolt 按钮 → quick-fill
3. **新增价格记录页**：字段渲染；价格/数量校验提示；保存调用 `createRecord`（repository mock）；返回后计价列表刷新
4. **起始页**：对话框三选一存 SharedPreferences；认证后 redirect 读配置落点
5. **回归**：全量测试绿 + `flutter analyze` 0 新增 + `flutter build windows` 通过

## 不做的事

- 不动 web 前端、后端
- 不动原料/商品上下文的 5 处 bottom sheet
