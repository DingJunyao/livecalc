# 自定义计算范围（多地区组合）

## 背景

住在行政区划边界附近的用户，价格数据横跨多个地区（如「灵宝市（县）+ 三门峡市（地级市）」）。现有机制只能表达「单个所在地区 + 单层级档位」（`users.region_id` + `default_calc_scope` ∈ ''/country/province/city/county），无法组合多个地区。本次新增：用户可创建多个「自定义计算范围」（名称 + 多个地区，层级可混合），并在「默认计算范围」选择器中选用；计算按所选范围的地区子树并集过滤。会话级顶栏切换器同步支持（问题未答复，按推荐执行）。

## 语义设计（核心决策）

- **多地区过滤 = 子树并集**：每个所选地区按现有 `region_subtree_ids`（path 前缀 + is_active）展开后取并集去重——选了地级市又选其下辖县不会重复计数；未分配地区（`region_id IS NULL`）的商家始终计入（既有约定不变）。
- **内部表示用 `tuple[int, ...]`**：`recipe_service.py:45,267` 把 region_id 用作 lookup_cache 的 dict key，必须可哈希，故 `resolve_region_param` 返回 `Optional[int | tuple[int, ...]]`，下游全部透传无需改动。
- **默认范围优先级**：`default_calc_scope_id`（自定义，**不要求** users.region_id 已设置）> 既有 `region_id + default_calc_scope` 路径；自定义范围查不到（被删）时回退既有路径。`''/all` = 全部地区、会话 all 短路默认、显式 query 参数 > X-Region > 用户默认——这些既有语义全部保留。
- **X-Region 头扩展**：`all` / 单 id（完全兼容）/ **逗号分隔多 id**（新增，≤20 个，任一非法→400，沿用现有报错文案）。
- **互斥写入**：`PATCH /me` 设 `default_calc_scope_id` 时清 `default_calc_scope`，反之亦然。
- **限额**：每用户 ≤20 个范围，每个范围 region_ids 去重后 ≤50 个。

- `app/services/session_context.py`：`set/get_session_region` 类型注解放宽为 `Optional[int | tuple]`，逻辑不变。
