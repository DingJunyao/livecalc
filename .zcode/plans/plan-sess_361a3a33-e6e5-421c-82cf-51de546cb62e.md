# 新增记价「搜索不到商品 → 新增商品」闭环

## Context

新增价格记录时输入商品名、搜索不到对应商品是高频场景。目前只能退到原料/商品页新建再回来；只有扫码才有「未命中 → 预填跳新增商品页 → 返回自动选中」的闭环。

调研确认的关键事实：
- **后端通路已存在**：`POST /products` 带 `product_name` 会 `_get_or_create_product` + 自动建同名原料（`backend/app/api/products.py:61-92`），**后端零改动**。
- **两端扫码闭环模式现成**：移动端 `price_record_form_screen.dart:345-389`（`push<ProductFormResult>('/products/new', extra: ProductFormPrefill)` → 返回 `_selectProduct`）；web `PricesView.vue:499-509 + 983-1001`（sessionStorage `barcode-new-product` → `/data/products?returnTo=` → `consumeReturnedProduct`）。
- **Web 校验矛盾**：`productIdRules` 标红「请选择或输入商品名称」，但 `saveRecord` 里 `if (!formRef.value?.validate()) return` 因 Vuetify 3 `validate()` 返回 Promise（truthy）而拦不住提交——显示错误却保存成功，`product_name` 回退实际可达。
- 移动端新增记价直接输名字保存**已经**隐式建商品（`_save` L443-454）；web 快速填写显式拦死；移动端编辑页换商品搜索无结果无入口。

**方案**（用户未确认，按推荐方向执行）：照抄扫码闭环——搜索无结果时显示「新增商品「xxx」」入口，预填名称跳新增商品页，返回自动选中；顺带修正 web 校验，使「直接输名字保存」成为两端一致的明确行为。覆盖主记价表单（两端）、移动端编辑页换商品、web 快速填写。

## Web（master 分支）

### 1. `frontend/src/views/prices/PricesView.vue`（主记价表单，新增/编辑共用）

- **「未找到」入口**：把现有 disabled 预览字段（L258-267）改造为可操作的提示块：显示「未找到「{name}」，将创建新商品」+「新增商品」按钮（append-inner 或并列按钮）。
- **跳转新增商品页**：新增 `goCreateProductByName()`，照抄 `goCreateProduct`（L499-509）：`sessionStorage['barcode-new-product']` 存 `{ name: productSearch }` → `router.push({ path: '/data/products', query: { name, returnTo: '/prices' } })`。
- **返回自动选中**：复用已有 `consumeReturnedProduct()`（onMounted 调用，L983-1001 会重新打开对话框并灌入 selectedProduct/product_id）。
- **校验修正**（两处）：
  - `productIdRules`（L699-701）按新增/编辑区分：新增态放宽为「选了商品 **或** 输入了名字」其一（`!!v || normalizeProductSearch(productSearch.value)`），编辑态保持必须选商品（PUT 不支持按名建）。rules 闭包读取响应式值，配合下面的 validate 修正。
  - `saveRecord`（L1004）：`if (!formRef.value?.validate()) return` → `const ok = await formRef.value?.validate(); if (ok?.valid === false) return`（Vuetify 3 正确用法），让校验真正生效且不再误标红。
  - 「直接输名字保存 → 后端隐式建商品」保留为兜底路径（与移动端一致）。

### 2. `frontend/src/views/prices/QuickFillView.vue`（快速填写）

- `#no-data` 槽（L156-158）由纯文字改为带「新增商品「{name}」」按钮。
- 点击 → `saveDraft()`（保存整页草稿）→ sessionStorage prefill `{ name: row.searchText }` → `router.push('/data/products?returnTo=/prices/quick-fill')`——与扫码流程 `goCreateProduct`（L629-639）完全同构。
- 返回后复用已有 `consumeProductReturn`（L641-652）+ `appendProductRow`（L567-578）把新商品加为新行。
- `saveAll` 的「新行必须选商品」守卫（L764-769）保留——返回后新行已自动选中商品。

## 移动端（feat/mobile-app 分支）

### 1. `mobile/lib/features/prices/screens/price_record_form_screen.dart`（新增记价）

- `_searchProducts` 完成后：`_searchResults.isEmpty && !_searching && 文字非空` 时，在结果 Card 区域（L593-606）渲染「未找到「{name}」，新增商品」入口（ListTile/Card）。

- 直接输名字保存的隐式建商品路径不动。

### 2. `mobile/lib/shared/screens/price_record_edit_screen.dart`（编辑换商品）

移动端快速填写页无搜索下拉（历史商品行），不涉及。
